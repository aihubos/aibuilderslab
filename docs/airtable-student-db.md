# AI 빌더스 랩 수강생 DB와 교육 신청 폼 (사용 중지)

> 현재 홈페이지는 Airtable 연동과 공개 Airtable 신청 폼을 사용하지 않습니다. 교육 신청은 당근 모임 댓글 또는 개인 카카오톡으로 받습니다. 이 문서는 과거 운영 참고용으로만 남겨둔 문서입니다.

## 먼저 할 일

1. Airtable에서 아래 네 개 테이블을 만듭니다.
2. `교육 신청 DB`에 공개 신청 폼을 만듭니다.
3. 폼 공유를 `Anyone on the web`으로 설정하고 `See who submitted`는 끕니다.
4. 실제 폼 공유 주소만 `site-config.js`의 `AIRTABLE_FORM_URL`에 넣습니다.

이 저장소는 Airtable API 키, Base ID, Table ID를 사용하지 않습니다. 공개 폼 주소만 웹사이트에 노출합니다.

## 접수 흐름

```text
공개 폼 제출
→ 교육 신청 DB에 접수 원본 생성
→ 운영자가 휴대전화 정규화 값으로 기존 빌더 확인
→ 기존 빌더 연결 또는 새 빌더 생성
→ 신청 상태, 일정, 출석, 결과물 관리
```

공개 폼에는 `빌더` 연결 필드를 표시하지 않습니다. 기존 빌더의 이름이 다른 신청자에게 보일 수 있기 때문입니다.

## 1. 빌더 DB

| 필드 | 형식 | 운영 규칙 |
|---|---|---|
| 빌더 순번 | 자동번호 | 내부용 |
| 빌더 ID | 수식 | `"BLD-" & RIGHT("0000" & {빌더 순번}, 4)` |
| 이름·활동명 | 한 줄 텍스트 | 필수 |
| 휴대전화 | 전화번호 | 비공개 |
| 휴대전화 정규화 | 수식 | `REGEX_REPLACE({휴대전화}, "[^0-9]", "")` |
| 당근 닉네임 | 한 줄 텍스트 | 선택 |
| Telegram·카카오 닉네임 | 한 줄 텍스트 | 선택 |
| 운영체제 | 단일 선택 | Windows, macOS, 기타 |
| AI 경험 수준 | 단일 선택 | 처음, 가끔 사용, 자주 사용, 제작 경험 있음 |
| 가입일 | 날짜 | 최초 등록일 |
| 마지막 활동일 | 날짜 | 재신청 또는 교육 참여 시 갱신 |
| 회원등급 | 단일 선택 | 참여자, 입문 빌더, 정식 빌더, 멘토. 기본값은 참여자 |
| 개인정보 동의 | 체크박스 | 신청 동의 확인 |
| 개인정보 동의일 | 날짜·시간 | 신청 접수 시점 |
| 삭제 예정일 | 수식 | `DATEADD({마지막 활동일}, 1, "year")` |
| 운영자 메모 | 긴 텍스트 | 절대 공개하지 않음 |

등급은 운영자가 직접 변경합니다. 자동 승급은 만들지 않습니다.

## 2. 교육 신청 DB

### 공개 폼에 표시하는 접수 필드

신청자의 작성 부담을 줄이기 위해 선택형을 우선 사용한다. 직접 입력은 이름·활동명, 휴대전화, 당근 닉네임, 만들고 싶은 결과물 또는 목표, 문의사항·기타사항만 사용한다.

1. 이름·활동명 — 짧은 입력, 필수
2. 휴대전화 — 짧은 입력, 필수. 안내: `예: 01012345678 · 하이픈(-) 없이 숫자만 입력해주세요.`
3. 당근 모임 닉네임 — 짧은 입력, 필수
4. 신청 과정 — 단일 선택: 개인 강의 / 정기 강의 / AI 빌더스 랩 정식 기수
5. 참여 가능한 요일 — 다중 선택: 월 / 화 / 수 / 목 / 금 / 토 / 일
6. 참여 가능한 시간대 — 다중 선택: 10:00~13:00 / 14:00~17:00 / 19:00~21:00 / 기타 시간 직접 입력
7. 노트북 운영체제 — 단일 선택: Windows / macOS / 기타
8. 현재 AI 사용 경험 — 단일 선택: 처음 사용 / 가끔 사용 / 자주 사용 / 직접 만들어본 경험 있음
9. 배우고 싶은 주제 — 다중 선택: AI 에이전트(Hermes Agent·OpenClaw) / 자동화 / 바이브 코딩 / 개인 대시보드 제작 / LLM Wiki / 기타 직접 입력
10. 만들고 싶은 결과물 또는 목표 — 짧은 입력, 필수
11. 교육을 알게 된 경로 — 단일 선택: 당근 / 카카오톡 / Telegram / 블로그 / 지인 / 기타
12. 개인정보 수집·이용 동의 — 필수 체크
13. 문의사항·기타사항 — 선택 긴 글 입력

### 내부 운영 필드

| 필드 | 형식 | 운영 규칙 |
|---|---|---|
| 신청 순번 | 자동번호 | 내부용 |
| 신청 ID | 수식 | `"APP-" & RIGHT("0000" & {신청 순번}, 4)` |
| 빌더 | 빌더 DB 연결 | 공개 폼에서 숨김 |
| 신청 과정 | 단일 선택 | 무료 입문, 주제별 실습, 1기, 기타 |
| 기수 | 텍스트 또는 단일 선택 | 예: 1기 |
| 신청일 | 생성 시간 | 자동 |
| 신청 상태 | 단일 선택 | 신청, 상담 중, 일정 확정, 결제 완료, 수강 중, 수료, 취소 |
| 교육비 | 통화 | 내부 입력 |
| 할인 유형 | 단일 선택 | 없음, 결과물 공유 50%, 후기 20%, 별도 확인 |
| 최종 결제금액 | 통화 | 내부 입력 |
| 결제 확인일 | 날짜 | 결제 상세정보는 저장하지 않음 |
| 환불 여부 | 체크박스 | 내부 입력 |
| 처리 완료일 | 날짜 | 취소·미참여 처리일 |
| 보관 기준일 | 날짜 | 처리 완료일 또는 마지막 교육일 |
| 삭제 예정일 | 수식 | `DATEADD({보관 기준일}, 1, "year")` |

할인 금액은 자동 계산하지 않습니다. 결과물 공유 50% 할인과 후기 20% 할인 중복 여부는 신청 전에 운영자가 확인합니다.

## 3. 출석·수업 기록 DB

한 회차마다 빌더별 기록 하나를 만듭니다.

| 필드 | 형식 |
|---|---|
| 기록 ID | 자동번호 또는 수식 |
| 빌더 | 빌더 DB 연결 |
| 교육 신청 | 교육 신청 DB 연결 |
| 기수 | 텍스트 또는 단일 선택 |
| 회차 | 숫자 또는 단일 선택 |
| 수업일 | 날짜 |
| 출석 상태 | 예정, 출석, 지각, 결석, 보강 |
| 설치 완료 항목 | 긴 텍스트 또는 다중 선택 |
| 실습 완료 여부 | 체크박스 |
| 어려웠던 부분 | 긴 텍스트 |
| 다음 회차 준비사항 | 긴 텍스트 |
| 강사 메모 | 긴 텍스트 |

## 4. 결과물·후기 DB

| 필드 | 형식 |
|---|---|
| 기록 ID | 자동번호 또는 수식 |
| 빌더 | 빌더 DB 연결 |
| 교육 신청 | 교육 신청 DB 연결 |
| 제출일 | 날짜 |
| 결과물 이름 | 한 줄 텍스트 |
| 결과물 링크 | URL |
| 자동화 테스트 횟수 | 숫자 |
| 후기 제출 여부 | 체크박스 |
| 후기 원문 | 긴 텍스트 |
| 사진 공개 동의 | 체크박스 |
| 후기 공개 동의 | 체크박스 |
| 결과물 공개 동의 | 체크박스 |
| 정식 빌더 조건 충족 여부 | 체크박스 |
| 운영자 확인일 | 날짜 |

신청 때 받은 공개 동의는 예비 의사입니다. 실제 사진, 후기, 결과물을 게시하기 전에는 이 테이블의 동의를 다시 확인합니다.

## 공개 Airtable 폼 설정

폼 제목은 `AI 빌더스 랩 교육 신청`으로 설정합니다.

### 필수 필드 순서

1. 이름·활동명
2. 휴대전화 — `예: 01012345678`, 하이픈(-) 없이 숫자만 입력
3. 당근 모임 닉네임
4. 신청 과정
5. 참여 가능한 요일
6. 참여 가능한 시간대
7. 노트북 운영체제
8. 현재 AI 사용 경험
9. 배우고 싶은 주제
10. 만들고 싶은 결과물 또는 목표
11. 교육을 알게 된 경로
12. 개인정보 수집·이용 동의

### 선택 입력

- 참여 가능한 시간대의 기타 시간
- 배우고 싶은 주제의 기타
- 문의사항·기타사항

개인정보 동의는 필수 체크박스로 만들고 기본 선택 상태로 두지 않습니다. 사진, 후기, 결과물 공개 동의는 모두 선택 항목입니다.

### 개인정보 동의 문구

```text
수집 항목: 이름 또는 활동명, 휴대전화, 메신저 닉네임,
교육 신청 내용과 교육 준비 정보

수집 목적: 신청 확인, 일정 조율, 교육 준비와 수강 기록 관리

보관 기간: 신청 처리 완료일 또는 마지막 교육 활동일로부터 1년

동의를 거부할 수 있으나, 교육 신청 확인과 일정 안내가 제한될 수 있습니다.
사진, 후기, 결과물 공개 동의는 각각 선택 사항이며
교육 신청 동의와 별도로 처리됩니다.
```

공개 폼에서는 `빌더` 연결, 비용, 할인, 결제, 운영자 메모를 숨깁니다. 공유는 `Anyone on the web`으로 설정하고 `See who submitted`는 끕니다.

제출 후 메시지는 다음으로 설정합니다.

```text
신청이 접수되었습니다.
운영자가 신청 과정과 참여 가능한 일정을 확인한 뒤 개별 안내합니다.
신청 직후 결제정보나 계정 비밀번호를 요청하지 않습니다.
```

## 운영 뷰

| 뷰 | 필터와 정렬 |
|---|---|
| 신규 신청자 | 신청 상태 = 신청. 신청일 오름차순 |
| 일정 확인 필요 | 신청 상태 = 신청 또는 상담 중. 참여 가능 일정이 있음 |
| 결제 확인 필요 | 신청 상태 = 일정 확정. 최종 결제금액 > 0. 결제 확인일이 비어 있음 |
| 1기 확정 빌더 | 신청 과정 = 1기. 기수 = 1기. 상태가 일정 확정 이후 |
| 회차별 출석부 | 기수와 회차로 그룹. 수업일과 이름 순 정렬 |
| 실습 미완료자 | 출석 상태 = 출석 또는 지각. 실습 완료 여부가 비어 있음 |
| 후기 요청 대상 | 신청 상태 = 수료. 후기 제출 여부가 비어 있음 |
| 정식 빌더 전환 검토 | 정식 빌더 조건 충족. 현재 회원등급은 정식 빌더가 아님 |
| 개인정보 삭제 예정 | 삭제 예정일이 30일 이내 |

## 중복 신청과 보관

1. 교육 신청 DB의 휴대전화에서 숫자만 추출합니다.
2. 운영자가 Airtable 내부에서 빌더 DB의 정규화 번호를 검색합니다.
3. 이름 또는 활동명과 닉네임을 함께 확인합니다.
4. 같은 사람으로 확인되면 기존 빌더를 연결합니다.
5. 확인되지 않으면 새 빌더를 생성합니다.

휴대전화가 같다는 이유만으로 자동 병합하지 않습니다. 브라우저나 공개 화면에서 중복 검색도 하지 않습니다.

미참여·취소 신청자는 처리 완료일, 참여자는 마지막 교육일, 재신청자는 가장 최근 활동일을 기준으로 1년 보관합니다. 매월 `개인정보 삭제 예정` 뷰를 확인해 만료 기록을 삭제합니다. 카드 번호, 계좌번호, API 키, 비밀번호, 주민등록번호, 상세 주소는 받거나 저장하지 않습니다.

## 아직 설정해야 하는 항목

- Airtable Base 생성
- 위 스키마의 네 테이블 생성
- 공개 신청 폼 생성과 필수·선택 항목 확인
- `site-config.js`에 실제 공개 폼 공유 URL 입력
- 실제 개인정보를 사용하지 않는 시험 제출 1건
- 개인정보 안내 문구의 운영자 최종 검토
